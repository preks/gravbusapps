# AI Builder Component Registration Fix

## Issue Summary

**Problem:** Screens published from the AI Builder appeared white with console errors:

```
Component not registered via standard exports pattern, checking fallbacks...
Failed to find a suitable component to register
Component '{screen-name}' registration failed: Component not found
```

**Root Cause:** The Forge API's wrapped entry file was only exporting the default export, but the platform's `remoteComponentLoader` requires **BOTH** default and named exports for component registration.

## The Fix

**File Modified:** `/Users/denisprekrat/Documents/APPS/NEWWORK Apps/forge/packages/api/src/routes/newwork-publish.ts`

**Lines:** 416-443

### Before (Only Default Export)

```typescript
const wrappedContent = `// Auto-generated by Forge publish
import { wrapWithUiCatalog } from '@/common/wrapWithUiCatalog';
import OriginalComponent from '@/business-apps/${body.screenPath}';

export default wrapWithUiCatalog(OriginalComponent);
`
```

### After (Both Default and Named Exports)

```typescript
// Extract component name from screen path (e.g., "absence-report" -> "AbsenceReport")
const screenName = body.screenPath.split('/').pop() || 'Component'
const componentName = screenName
  .split('-')
  .map(word => word.charAt(0).toUpperCase() + word.slice(1))
  .join('')

// CRITICAL: Include BOTH named and default exports to support platform component loader
const wrappedContent = `// Auto-generated by Forge publish
import { wrapWithUiCatalog } from '@/common/wrapWithUiCatalog';
import OriginalComponent, { ${componentName} } from '@/business-apps/${body.screenPath}';

// Wrap the component with UiCatalog provider
const WrappedComponent = wrapWithUiCatalog(OriginalComponent);

// Export both default and named - BOTH are required for platform component registration
export default WrappedComponent;
export { WrappedComponent, ${componentName} };
`
```

## Why This Fixes the Issue

### Platform Component Loader Requirements

The platform's `remoteComponentLoader.ts` expects remote components to have:

1. **Default export** - For `import Component from './index'` pattern
2. **Named export** - For component type validation and registration

When the wrapped entry only had the default export, the loader couldn't validate the component type and failed registration.

### What Changed

1. **Component Name Extraction**: Converts kebab-case screen name to PascalCase component name
   - `absence-report` → `AbsenceReport`
   - `team-members-report` → `TeamMembersReport`

2. **Named Import**: Imports both default and named export from the source component

   ```typescript
   import OriginalComponent, { AbsenceReport } from '@/business-apps/hr/common/apps/absence-report'
   ```

3. **Wrapped Component**: Creates a wrapped version with a name

   ```typescript
   const WrappedComponent = wrapWithUiCatalog(OriginalComponent)
   ```

4. **Dual Exports**: Re-exports both formats
   ```typescript
   export default WrappedComponent
   export { WrappedComponent, AbsenceReport }
   ```
