### 1.4 Real-Time Synchronization Patterns

**Process Completion Events** (Used throughout the platform):
```typescript
const eventNames = [
  'com.newwork.process.taskCompletion',
  'com.newwork.process.completion', 
  'com.newwork.process.continue',
  'com.newwork.process.processCompletion',
  'processCompletion',
  'taskCompletion'
];

// Standard pattern for real-time refresh
useEffect(() => {
  const handleProcessCompletion = (event: any) => {
    if (event.detail?.resolution === 'success') {
      loadData(); // Refresh data
    }
  };

  eventNames.forEach(eventName => {
    window.addEventListener(eventName, handleProcessCompletion);
  });

  return () => {
    eventNames.forEach(eventName => {
      window.removeEventListener(eventName, handleProcessCompletion);
    });
  };
}, [loadData]);
```

## 5. Alternative Approach: Build CRM-Specific Profile (IF REQUIRED)

**⚠️ Only proceed with this if business explicitly requires a separate CRM profile distinct from Employee Record.**

### Why This is NOT Recommended
1. **Code Duplication**: 95% overlap with Employee Record
2. **Maintenance Burden**: Two profile systems to maintain
3. **User Confusion**: Why do I have two profiles?
4. **Data Inconsistency Risk**: Same data in two places
5. **Wasted Development Time**: 3-4 weeks vs. 2 hours

### If You Must Build a New App
