# Project Description

## Project Overview

This is a React TypeScript project for building business application microfrontends within the NEWWORK platform. Each component should extend `BusinessAppContextProps` and follow established patterns for data integration, UI components, and API communication.

- ALWAYS read the .cursor/rules/newwork-gravity-business-apps.mdc to understand the context of this project

# Code Quality

- Follow SOLID principles
- Apply DRY (Don't Repeat Yourself) principle
- Keep methods small and focused
- ALWAYS follow OWASP best practices.
- Use meaningful names for classes, methods, and variables
- Apply consistent code formatting (Google Typescript Style)

# Code Development

- No single file should exceed 300 lines of code (excluding imports and blank lines). When a file approaches this size, break out logic, UI, hooks, or utility functions into separate, logically named files.
- If splitting is not obvious, prompt the user for suggestions on how to divide the code.
- Make usage of existing code, functions or components
- Remove commented code

# Component Dependencies

- Always use tailwind v3 for all styling (utility classes). Never use other styling libraries (e.g. styled-components). Never use other styling mechanisms (e.g. CSS files / modules). Never use inline styles.
- The list of required dependencies must be small and simple and must reuse existing packages.

# i18n

- ALWAYS ensure all UIs have proper internationalization, never display hardcoded text in the UI.
- For all date and time related logic, use `windowUtils.formatDate`, `windowformatDateUtils` is imported from `src/common/utils/windowUtils.ts`.
- For all numbers related logic, use `windowUtils.formatNumberFunction`, `formatNumberFunction` is imported from `src/common/utils/windowUtils.ts`.
- All labels must be translated using `windowUtils.getTranslationFromI18nKeyAndLabel`, `getTranslationFromI18nKeyAndLabel` is imported from `src/common/utils/windowUtils.ts`.

# UI Component Patterns

## Library

- **Design System**: Strictly always use the "@newwork/nw-design-system" library for components. Do not use antd Do not use the gravity-ui-catalog.

## Styling Guidelines

- **CSS Classes**: Always prefix with `gba:` (e.g., `gba:bg-blue-500`)
- **Framework**: Use Tailwind v4 utility classes
- **Global CSS**: Add all CSS files to `src/index.css` for Vite bundling

# API Requests

- Never use `axios` or `fetch` directly.

## GraphQL API Integration

- **Client**: Use `useGraphQLClient()` from `src/common/network/graphql/useGraphQLClient.ts`
- **Query Structure**: Create query files in `queries/` directory with pattern `EntityQueries.ts`
- **Hook Pattern**: Create data hooks in `hooks/` directory with pattern `useEntityData.ts`

## Catalog API Integration

- **Client**: Use `useCatalogManagerClient()` from `src/common/network/catalogs/useCatalogManagerClient.ts`
- **Pattern**: Create catalog hooks in `hooks/` directory with pattern `useEntityCatalog.ts`

## Data Integration Hook Pattern

- **Purpose**: Combine multiple data sources (GraphQL + Catalog) into a single hook
- **Pattern**: Create integration hooks with pattern `useEntityDataIntegration.ts`
- **Features**: Parallel data fetching, data transformation, enhanced interfaces, loading/error states

## API Errors

- Always wrap API calls in try-catch blocks
- Provide meaningful error messages to users
- Log errors for debugging (without sensitive data)
- Implement retry mechanisms where appropriate

## Service URLs

- Never use hardcoded base URLs like `https://newwork-dev.newwork.com/<rest_of_the_base_url>`. Always use `env` from `'@/utils/env-vars.utils'`. The `env` function gets the key of the base url as a string argument.
